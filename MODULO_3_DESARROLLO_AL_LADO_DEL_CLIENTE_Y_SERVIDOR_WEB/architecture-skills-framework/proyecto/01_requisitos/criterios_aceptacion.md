# Criterios de aceptación para la validación de requisitos

## Sistema seleccionado

**SIGICI-RI – Sistema Inteligente de Gestión de Incidentes de Ciberseguridad y Respuesta Institucional**

## Criterios de aceptación

- **CA-01.** Cada requerimiento funcional deberá expresar una capacidad o comportamiento esperado del sistema.

- **CA-02.** Cada requerimiento deberá estar identificado mediante un código único RF o RNF.

- **CA-03.** Los requerimientos deberán redactarse de forma clara y comprensible, evitando expresiones ambiguas.

- **CA-04.** Los requerimientos no funcionales deberán ser medibles o verificables cuando corresponda.

- **CA-05.** No deberán existir contradicciones entre requerimientos funcionales y no funcionales.

- **CA-06.** No deberán existir duplicidades innecesarias entre los requerimientos.

- **CA-07.** Los requerimientos deberán describir necesidades del sistema y no imponer prematuramente tecnologías, lenguajes, frameworks, arquitecturas o motores de base de datos.

- **CA-08.** Los requerimientos relacionados con seguridad deberán permitir identificar posteriormente criterios objetivos de protección, acceso, auditoría e integridad.

- **CA-09.** El conjunto de requerimientos deberá cubrir como mínimo el registro, clasificación, asignación, seguimiento, escalamiento, resolución, cierre y trazabilidad de incidentes.

- **CA-10.** Toda observación producida por el agente deberá estar relacionada con uno o más RF/RNF identificables.

- **CA-11.** El agente actuará únicamente como validador inicial. La aceptación o rechazo de cada observación corresponderá al estudiante.

- **CA-12.** Toda observación aceptada deberá generar una mejora justificable en claridad, completitud, consistencia o verificabilidad.

- **CA-13.** Toda observación rechazada deberá contar con una justificación breve basada en el contexto y necesidades reales del sistema.

- **CA-14.** En esta etapa no se seleccionará una tecnología, lenguaje de programación, framework, arquitectura ni motor de base de datos definitivo.

- **CA-15.** La versión final de los RF/RNF deberá conservar trazabilidad respecto de su versión inicial y de las observaciones aceptadas.
